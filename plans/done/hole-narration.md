# ✅ 完了 穴の語りの印（行頭 "~ "）

見本の「穴」（作る人が自分の話に替える所）の仮の語りが、語り手の画面でほかの語りと見分けられない。
演出の行（`> `）と同じ見た目にすると読み飛ばされるので、読む文のまま、蛍光ペンの形で出す。

## 決めたこと

- 印は行頭の `~ `（半角のチルダと空白）。段落の各行に付ける。`> ` の行（合図）とは別の種類: **読む文**
- work.json の `notes` には印を**残す**（`> ` と同じ扱い）。理由:
  - 語り手の画面が、どの行が穴かを知るのに別の欄が要らない
  - 修正票は notes の段落で前後を書く。script.md にも印があるので、票を台本へ書き戻すとき段落が合う
  - 直す欄で自分の話に替えたら、印を消せば穴でなくなる（印が文と一緒に動く）
- 印の文字は画面にも読み上げ台本にも出さない: プレイヤーは印を外して出す。発表者ノートなどへ書き出す道具は印を外す（形式に書く）
- 似ているが印でない行は警告（止めない）: 全角の `～ `・波ダッシュ `〜 `、空白の無い `~語り`、印だけで語りの無い行
- 聞き手には何も変わらない（notes は送らない。R1）

## 手順

1. build_work.py: 印に似た行の警告。notes には印を残す
2. tests/builder: 印が残る・太字が外れる・警告
3. narrator.js: `~ ` の行を `.hole`（字は黒・普通、背景だけ薄い黄色）。app.css に `--hole-bg`（ダークも）
4. docs/work-format.md: §2.3 の表・§3 notes・§5 の検査
5. Skill: script-template.md の記法・SKILL.md §3・starting-from-a-seed.md。plugin の版 0.8.0 → 0.9.0
6. tests/e2e/hole_mark.py: 語り手の画面で黄色の背景・印が見えない・合図と違う見た目・ダークの色・聞き手に台本が出ない
7. 見本2本に印を付けるのは別のセッション（ここではしない）
