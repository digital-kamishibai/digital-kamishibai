# ✅ 完了 BGM の曲の大きさをそろえる

依頼（2026-11-09、見本2本目の作業から。持ち主が承認）: 見本の曲を自分の曲に差し替えると、CD・配信の曲（-10〜-14 LUFS）は
見本の曲（-30〜-34 LUFS）より約20dB 大きく鳴り、語りを消す。作り手が何もしなくても、語りの下に敷ける大きさにそろえる。

## 決めたこと

- **測るのは語り手のプレイヤー**（ビルダーではない）。ファイルを入れ替えただけでビルドし直さない人にも効く。ffmpeg も要らない
  （チャットの AI の箱にも ffmpeg が無いことがある）。語り手は PC なので、曲を丸ごと読み解いてもメモリは足りる
- 測り方: ITU-R BS.1770-4 の統合ラウドネス（K 特性・400ms の区切り・-70 LUFS と -10 LU のゲート）。`player/js/loudness.js`（純粋な関数）
- **大きすぎる曲だけ下げる**: 目標 -30 LUFS。-29 LUFS（目標＋1）より大きい曲を -30 まで下げる。小さい曲は上げない（割れる・雑音が上がる）
  - 見本の曲（-30.6〜-33.8 LUFS）は変わらない。ffmpeg とのずれが少しあっても、1 LU の余裕で変わらない
- 対象は `[BGM]`・`[BGM once]`・`[BGM after video]` の曲だけ。効果音（短い・一瞬）と動画の音は対象にしない
- 聞き手へは welcome の `audio[].gain`（dB、0 以下）で渡す。聞き手の端末も語り手の端末も、曲の GainNode に掛ける（録画にも入る）
- 測るのは準備の画面で、受付へ進む前（開演より前に済む）。同じ曲（同じ id）は localStorage に覚えて、2回目からは測らない
- 読み解けない曲は 0 dB（そのまま）。準備の画面で下げた曲を1行で知らせる

## 手順

1. `loudness.js` とテスト（1kHz の正弦波で -3.01 LUFS、ゲート、下げる量）
2. engine（deck の大きさ）・narrator（測る・覚える・知らせる）・protocol（welcome）・listener
3. i18n（ja・en）、docs/work-format.md（「プレイヤーは曲の大きさをそろえない」を直す）
4. 見本1本目の bgm.mp3 で ffmpeg と突き合わせる（一度だけ）。e2e: 大きい曲と小さい曲で、語り手と聞き手の deck の大きさを見る
